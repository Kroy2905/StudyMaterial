Pattern Printing

Nested-loop warm-ups. The trick is always the same: work out, for row i, how many spaces and how many symbols to print, as a formula in i and n.

Q1Print a right-angled triangle and an inverted triangle of starsEasy

Problem. Given n, print n rows where row i has i stars, then the same shape upside down.

Approach. The outer loop picks the row; the inner loop prints as many stars as the row number. Reversing the outer loop (downTo) flips the shape without touching the body.

Pseudocode

FUNCTION rightTriangle(n)
    FOR row FROM 1 TO n              // row i prints i stars
        FOR col FROM 1 TO row
            PRINT "*"
        PRINT newline

FUNCTION invertedTriangle(n)
    FOR row FROM n DOWN TO 1         // same body, loop runs backwards
        FOR col FROM 1 TO row
            PRINT "*"
        PRINT newline

Kotlin

fun rightTriangle(n: Int) {
    for (row in 1..n) {
        for (col in 1..row) print("*")      // inner loop bound depends on the outer variable
        println()
    }
}

fun invertedTriangle(n: Int) {
    for (row in n downTo 1) {
        for (col in 1..row) print("*")
        println()
    }
}

fun main() {
    rightTriangle(4)
    println("--")
    invertedTriangle(4)
}

Q2Print a centered pyramid, and a hollow pyramidEasy

Problem. Print a pyramid of height n centered on a fixed width; then print only its outline.

Approach. Row i needs n - i leading spaces and 2i - 1 stars (1, 3, 5...). For the hollow version, print a star only on the first column, the last column, or the base row, and a space everywhere else.

Pseudocode

FUNCTION pyramid(n)
    FOR row FROM 1 TO n
        FOR s FROM 1 TO n - row          // leading spaces shrink: n-1, n-2, ... 0
            PRINT " "
        FOR k FROM 1 TO 2 * row - 1      // stars grow by 2: 1, 3, 5, ...
            PRINT "*"
        PRINT newline

Kotlin

fun pyramid(n: Int) {
    for (row in 1..n) {
        for (s in 1..n - row) print(" ")         // empty range when row == n → no spaces
        for (k in 1..2 * row - 1) print("*")
        println()
    }
}

fun hollowPyramid(n: Int) {
    for (row in 1..n) {
        print(" ".repeat(n - row))
        for (k in 1..2 * row - 1) {
            val edge = k == 1 || k == 2 * row - 1 || row == n  // first/last column or base row
            print(if (edge) "*" else " ")
        }
        println()
    }
}

fun main() {
    pyramid(4)
    println("--")
    hollowPyramid(4)
}

Q3Print a diamondEasy

Problem. Print a diamond whose widest row is 2n - 1 stars.

Approach. A diamond is a pyramid (1..n) followed by the same pyramid reversed (n-1 downTo 1). Start the bottom half at n - 1 so the middle row isn't printed twice. Extracting printRow(n, row) keeps both halves to one line each.

Pseudocode

FUNCTION diamond(n)
    FOR row FROM 1 TO n                  // top half = pyramid
        printRow(n, row)
    FOR row FROM n - 1 DOWN TO 1         // bottom half = pyramid reversed, without repeating the middle
        printRow(n, row)

FUNCTION printRow(n, row)
    PRINT (n - row) spaces, then (2 * row - 1) stars, then newline

Kotlin

fun printRow(n: Int, row: Int) = println(" ".repeat(n - row) + "*".repeat(2 * row - 1))

fun diamond(n: Int) {
    for (row in 1..n) printRow(n, row)
    for (row in n - 1 downTo 1) printRow(n, row)
}

fun main() {
    diamond(4)
}

Q4Number patterns: Floyd's triangle and Pascal's triangleMedium

Problem. Print Floyd's triangle (consecutive numbers, row i has i of them) and the first n rows of Pascal's triangle.

Approach. Floyd: keep one counter outside both loops and increment it on every print. Pascal: every row starts and ends with 1, and each inner value is the sum of the two values above it. Build each row from the previous one; zipWithNext gives you exactly those adjacent pairs.

Pseudocode

FUNCTION floyd(n)
    counter = 1
    FOR row FROM 1 TO n
        FOR col FROM 1 TO row
            PRINT counter; counter = counter + 1
        PRINT newline

FUNCTION pascal(n)
    row = [1]
    REPEAT n TIMES
        PRINT row
        next = [1]
        FOR i FROM 1 TO size(row) - 1
            APPEND row[i - 1] + row[i] TO next   // each inner value = sum of the two above it
        APPEND 1 TO next
        row = next

Kotlin

fun floyd(n: Int) {
    var counter = 1
    for (row in 1..n) {
        println((1..row).joinToString(" ") { (counter++).toString() })
    }
}

fun pascal(n: Int) {
    var row = listOf(1)
    repeat(n) {
        println(" ".repeat(n - it - 1) + row.joinToString(" "))   // indent to centre it
        row = listOf(1) + row.zipWithNext { a, b -> a + b } + listOf(1)
    }
}

fun main() {
    floyd(4)
    println("--")
    pascal(5)
}

Sorting Algorithms

Expect to write at least one O(n²) sort and one O(n log n) sort from memory, trace it on a small array, and state its complexity and stability.

Q5Bubble sort with early exitEasy

Problem. Sort an integer array in place using bubble sort, and stop as soon as the array is sorted.

Approach. Repeatedly compare adjacent pairs and swap them if they are out of order. After pass k, the largest k items have "bubbled" to the end, so the inner loop can shrink. If a whole pass makes no swap, the array is sorted. That flag is what makes the best case O(n).

Pseudocode

FUNCTION bubbleSort(arr)
    n = length(arr)
    FOR pass FROM 0 TO n - 2
        swapped = false
        FOR j FROM 0 TO n - 2 - pass         // the last `pass` items are already in place
            IF arr[j] > arr[j + 1] THEN
                SWAP arr[j], arr[j + 1]
                swapped = true
        IF NOT swapped THEN BREAK            // no swaps → sorted → best case O(n)

Kotlin

fun IntArray.swap(a: Int, b: Int) { val t = this[a]; this[a] = this[b]; this[b] = t }

fun bubbleSort(arr: IntArray) {
    val n = arr.size
    for (pass in 0 until n - 1) {
        var swapped = false
        for (j in 0 until n - 1 - pass) {
            if (arr[j] > arr[j + 1]) {          // strict > keeps equal items in order → stable
                arr.swap(j, j + 1)
                swapped = true
            }
        }
        println("after pass ${pass + 1}: ${arr.contentToString()}")
        if (!swapped) break
    }
}

fun main() {
    bubbleSort(intArrayOf(5, 1, 4, 2, 8))
}

after pass 2: [1, 2, 4, 5, 8]
after pass 3: [1, 2, 4, 5, 8]
Time: O(n²) worst/average, O(n) best (already sorted) · Space: O(1), in place · Stable

Follow-ups interviewers ask:

  • Why is it stable? It only swaps on strict >, so equal items never pass each other.
  • Where is it actually useful? Almost nowhere in production. It is asked to check loop reasoning.
Q6Selection sortEasy

Problem. Sort an array by repeatedly selecting the minimum of the unsorted part.

Approach. For each position i, scan the rest of the array for the smallest item and swap it into place. It always does about n²/2 comparisons, even on sorted input, but at most n − 1 swaps, which is its one advantage when writes are expensive.

Pseudocode

FUNCTION selectionSort(arr)
    FOR i FROM 0 TO n - 2
        minIdx = i
        FOR j FROM i + 1 TO n - 1            // find the smallest item in the unsorted part
            IF arr[j] < arr[minIdx] THEN minIdx = j
        SWAP arr[i], arr[minIdx]             // put it at the front of the unsorted part

Kotlin

fun IntArray.swap(a: Int, b: Int) { val t = this[a]; this[a] = this[b]; this[b] = t }

fun selectionSort(arr: IntArray) {
    for (i in 0 until arr.size - 1) {
        var minIdx = i
        for (j in i + 1 until arr.size) {
            if (arr[j] < arr[minIdx]) minIdx = j
        }
        if (minIdx != i) arr.swap(i, minIdx)   // at most n-1 swaps in total
        println("i=$i: ${arr.contentToString()}")
    }
}

fun main() {
    selectionSort(intArrayOf(64, 25, 12, 22, 11))
}
i=0: [11, 25, 12, 22, 64]
i=1: [11, 12, 25, 22, 64]
i=2: [11, 12, 22, 25, 64]
i=3: [11, 12, 22, 25, 64]
Time: O(n²) in every case · Space: O(1), in place · Not stable

Follow-ups interviewers ask:

  • Why not stable? The long-distance swap can jump an item over an equal one. Example: [4a, 4b, 1] becomes [1, 4b, 4a].
Q7Insertion sortEasy

Problem. Sort an array the way you sort playing cards in your hand.

Approach. Keep a sorted prefix. Take the next item (key), shift every larger item in the prefix one step right, and drop key into the gap. On nearly sorted data almost nothing moves, so it runs in close to linear time.

Pseudocode

FUNCTION insertionSort(arr)
    FOR i FROM 1 TO n - 1
        key = arr[i]                         // the next card to insert
        j = i - 1
        WHILE j >= 0 AND arr[j] > key        // shift bigger items one step right
            arr[j + 1] = arr[j]
            j = j - 1
        arr[j + 1] = key                     // drop the card into the gap

Kotlin

fun insertionSort(arr: IntArray) {
    for (i in 1 until arr.size) {
        val key = arr[i]
        var j = i - 1
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j]
            j--
        }
        arr[j + 1] = key
        println("insert $key: ${arr.contentToString()}")
    }
}

fun main() {
    insertionSort(intArrayOf(12, 11, 13, 5, 6))
}
insert 11: [11, 12, 13, 5, 6]
insert 13: [11, 12, 13, 5, 6]
insert 5: [5, 11, 12, 13, 6]
insert 6: [5, 6, 11, 12, 13]
Time: O(n²) worst, O(n) best (nearly sorted) · Space: O(1), in place · Stable

Follow-ups interviewers ask:

  • Real libraries (TimSort, introsort) switch to insertion sort for small subarrays (roughly fewer than 16–32 items) because it has very low overhead.
  • Shifting instead of swapping does one write per move instead of three.
Q8Merge sortMedium

Problem. Sort an array in O(n log n) using divide and conquer.

Approach. Divide the array in half, recursively sort each half, then merge the two sorted halves by repeatedly taking the smaller front element. The recursion is log n levels deep and each level does O(n) merging work. Using <= in the merge takes from the left half on ties, which keeps the sort stable.

Pseudocode

FUNCTION mergeSort(arr)
    IF length(arr) <= 1 THEN RETURN arr      // base case
    mid = length(arr) / 2
    left  = mergeSort(arr[0 .. mid))         // divide
    right = mergeSort(arr[mid .. end))
    RETURN merge(left, right)                // conquer

FUNCTION merge(a, b)
    result = []; i = 0; j = 0
    WHILE i < length(a) AND j < length(b)
        IF a[i] <= b[j] THEN APPEND a[i++]   // <= keeps equal items in order → stable
        ELSE APPEND b[j++]
    APPEND the rest of a, then the rest of b
    RETURN result

Kotlin

fun mergeSort(arr: IntArray, depth: Int = 0): IntArray {
    if (arr.size <= 1) return arr
    val mid = arr.size / 2
    val left = mergeSort(arr.copyOfRange(0, mid), depth + 1)
    val right = mergeSort(arr.copyOfRange(mid, arr.size), depth + 1)
    return merge(left, right).also {
        println("  ".repeat(depth) + "merge ${left.contentToString()} + ${right.contentToString()} → ${it.contentToString()}")
    }
}

fun merge(a: IntArray, b: IntArray): IntArray {
    val out = IntArray(a.size + b.size)
    var i = 0; var j = 0; var k = 0
    while (i < a.size && j < b.size) out[k++] = if (a[i] <= b[j]) a[i++] else b[j++]
    while (i < a.size) out[k++] = a[i++]
    while (j < b.size) out[k++] = b[j++]
    return out
}

fun main() {
    println(mergeSort(intArrayOf(38, 27, 43, 3, 9, 82)).contentToString())
}

Follow-ups interviewers ask:

  • Merge sort is the natural choice for linked lists (no random access is needed and the merge needs no extra array) and for external sorting of files too big for memory.
  • Reduce allocations by merging into one reusable buffer instead of copying subarrays.
  • Merge k sorted lists: use a min-heap. Count inversions: count during the merge step.
Q9Quick sort (Lomuto partition)Medium

Problem. Sort an array in place in average O(n log n).

Approach. Partition around a pivot so smaller items end up on its left and larger ones on its right. The pivot is then in its final position. Recurse on both sides. Lomuto partition keeps a boundary i: everything before i is less than the pivot.

Pseudocode

FUNCTION quickSort(arr, lo, hi)
    IF lo >= hi THEN RETURN
    p = partition(arr, lo, hi)               // pivot is now at its final index p
    quickSort(arr, lo, p - 1)
    quickSort(arr, p + 1, hi)

FUNCTION partition(arr, lo, hi)              // Lomuto scheme
    pivot = arr[hi]
    i = lo                                   // arr[lo .. i) holds items < pivot
    FOR j FROM lo TO hi - 1
        IF arr[j] < pivot THEN
            SWAP arr[i], arr[j]; i = i + 1
    SWAP arr[i], arr[hi]
    RETURN i

Kotlin

fun IntArray.swap(a: Int, b: Int) { val t = this[a]; this[a] = this[b]; this[b] = t }

fun quickSort(arr: IntArray, lo: Int = 0, hi: Int = arr.size - 1) {
    if (lo >= hi) return
    val p = partition(arr, lo, hi)
    println("pivot ${arr[p]} at index $p: ${arr.contentToString()}")
    quickSort(arr, lo, p - 1)
    quickSort(arr, p + 1, hi)
}

fun partition(arr: IntArray, lo: Int, hi: Int): Int {
    val pivot = arr[hi]                      // production code picks a random/median pivot instead
    var i = lo
    for (j in lo until hi) {
        if (arr[j] < pivot) { arr.swap(i, j); i++ }
    }
    arr.swap(i, hi)
    return i
}

fun main() {
    val arr = intArrayOf(10, 80, 30, 90, 40, 50, 70)
    quickSort(arr)
    println(arr.contentToString())
}

Time: O(n log n) average, O(n²) worst (bad pivots, e.g. already sorted input with a last-element pivot) · Space: O(log n) recursion stack · Not stable

Follow-ups interviewers ask:

  • Avoid the worst case with a random or median-of-three pivot. Recurse into the smaller side first to keep the stack at O(log n).
  • Many duplicates? Use 3-way (Dutch national flag) partitioning.
  • Quickselect uses the same partition to find the k-th smallest item in average O(n).
Q10Comparator vs Comparable: sort objects by several fields, and which sort the library usesMedium

Problem. Sort employees by salary (high to low) with ties broken by name, and give a Version class a natural ordering so that 1.10 > 1.2.

Approach. Comparable is the type's single natural ordering, implemented inside the class (compareTo). A Comparator is a separate object, so you can have as many orderings as you need. In Kotlin, chain compareBy / thenBy; in Java, Comparator.comparing(...).thenComparing(...).

Pseudocode

// Comparator = a separate "how to compare" object → many orderings for one type
SORT employees BY salary DESCENDING, THEN BY name ASCENDING

// Comparable = the type's ONE natural ordering, built into the class
CLASS Version IMPLEMENTS Comparable
    FUNCTION compareTo(other)
        IF major != other.major THEN RETURN major - other.major
        RETURN minor - other.minor           // negative = less, 0 = equal, positive = greater

Kotlin

data class Employee(val name: String, val dept: String, val salary: Int)

data class Version(val major: Int, val minor: Int) : Comparable<Version> {
    override fun compareTo(other: Version) =
        compareValuesBy(this, other, { it.major }, { it.minor })   // natural ordering
    override fun toString() = "$major.$minor"
}

fun main() {
    val staff = listOf(
        Employee("Cara", "Eng", 120), Employee("Abe", "Eng", 120),
        Employee("Ben", "Ops", 90), Employee("Dan", "Eng", 150),
    )
    println(staff.sortedBy { it.salary }.map { it.name })      // stable: Cara stays before Abe
    println(staff.sortedWith(compareByDescending<Employee> { it.salary }.thenBy { it.name }).map { it.name })
    println(staff.groupBy { it.dept }.mapValues { (_, list) -> list.maxOf { it.salary } })

    val versions = listOf(Version(1, 10), Version(1, 2), Version(0, 9))
    println(versions.sorted())                                 // uses compareTo
    println(versions.max())
    println("1.10" > "1.2")                                    // why not compare strings: lexicographic!
}

Follow-ups interviewers ask:

  • compareTo must be consistent with equals, otherwise TreeSet/TreeMap will treat "equal by comparison" objects as duplicates.
  • Never write a - b in a comparator for arbitrary ints: it overflows. Use Integer.compare(a, b) or compareValues.

Interfaces & Single-Class Design

"Write a class that..." questions test encapsulation, validation, polymorphism and thread safety more than algorithms. Talk through the public API first, then the invariants you protect.

Q11Design a Shape interface hierarchy with polymorphic area()Easy

Problem. Model Circle, Rectangle and Triangle so that client code can compute areas and descriptions without knowing the concrete type.

Approach. Put the contract in an interface (area(), name) and shared behaviour in a default method (describe()). Each class implements only what differs. The client loops over a List<Shape> and dynamic dispatch calls the right area(). That is polymorphism, and adding a new shape needs no change to the client (Open/Closed).

Pseudocode

INTERFACE Shape
    name
    FUNCTION area()                          // abstract: every shape must implement it
    FUNCTION describe()                      // default method: shared by all shapes
        RETURN name + " with area " + area()

CLASS Circle(radius) IMPLEMENTS Shape        area = PI * r * r
CLASS Rectangle(w, h) IMPLEMENTS Shape       area = w * h
CLASS Triangle(base, h) IMPLEMENTS Shape     area = base * h / 2

shapes = [Circle(1), Rectangle(2, 3), Triangle(3, 4)]
FOR EACH s IN shapes: PRINT s.describe()     // polymorphism: one call, the right area() at runtime

Kotlin

import kotlin.math.PI

interface Shape {
    val name: String
    fun area(): Double
    fun describe() = "$name with area ${"%.2f".format(area())}"   // default implementation
}

class Circle(private val radius: Double) : Shape {
    override val name = "Circle"
    override fun area() = PI * radius * radius
}

class Rectangle(private val w: Double, private val h: Double) : Shape {
    override val name = "Rectangle"
    override fun area() = w * h
}

class Triangle(private val base: Double, private val height: Double) : Shape {
    override val name = "Triangle"
    override fun area() = base * height / 2
}

fun main() {
    val shapes: List<Shape> = listOf(Circle(1.0), Rectangle(2.0, 3.0), Triangle(3.0, 4.0))
    shapes.forEach { println(it.describe()) }
    println("total = %.2f".format(shapes.sumOf { it.area() }))
    println("largest = " + shapes.maxBy { it.area() }.name)
}

Java

import java.util.List;

public class Shapes {
    interface Shape {
        String name();
        double area();
        default String describe() {                 // Java 8+ default method
            return String.format("%s with area %.2f", name(), area());
        }
    }

    record Circle(double radius) implements Shape {
        public String name() { return "Circle"; }
        public double area() { return Math.PI * radius * radius; }
    }

    record Rectangle(double w, double h) implements Shape {
        public String name() { return "Rectangle"; }
        public double area() { return w * h; }
    }

    record Triangle(double base, double height) implements Shape {
        public String name() { return "Triangle"; }
        public double area() { return base * height / 2; }
    }

    public static void main(String[] args) {
        List<Shape> shapes = List.of(new Circle(1), new Rectangle(2, 3), new Triangle(3, 4));
        for (Shape s : shapes) System.out.println(s.describe());
        double total = shapes.stream().mapToDouble(Shape::area).sum();
        System.out.println(String.format("total = %.2f", total));
    }
}

Follow-ups interviewers ask:

  • Interface vs abstract class: use an abstract class when the shapes need shared state or a constructor (e.g. a color field); otherwise prefer an interface, since a class can implement many.
  • Should Square extend Rectangle? Not if Rectangle is mutable: setWidth on a Square breaks its invariant. That is the classic Liskov Substitution violation. Make shapes immutable or keep them siblings.
  • With a sealed interface, a when over shapes can be checked for exhaustiveness.
Q12Design a thread-safe BankAccount classMedium

Problem. Write a BankAccount with deposit, withdraw and transfer that never goes negative, rejects bad input, keeps a transaction history, and is safe to use from many threads.

Approach. Encapsulate the balance: a public getter and a private set, so it only changes through methods that check the rules. Validate arguments with require (IllegalArgumentException) and use a domain exception for business rule failures. Synchronize the mutators. For transfers, always lock the two accounts in the same global order (by id), so two opposite transfers can't deadlock.

Pseudocode

CLASS BankAccount(owner, initial)
    PRIVATE balance                          // readable from outside, changed only by methods
    PRIVATE history = []

    FUNCTION deposit(amount)     SYNCHRONIZED
        REQUIRE amount > 0
        balance += amount; history.add("+amount")

    FUNCTION withdraw(amount)    SYNCHRONIZED
        REQUIRE amount > 0
        IF amount > balance THEN THROW InsufficientFunds
        balance -= amount; history.add("-amount")

Q13Implement a thread-safe Singleton (Kotlin object, double-checked locking, holder idiom)Medium

Problem. Guarantee exactly one instance of a class, created lazily, even when many threads ask for it at the same time.

Approach. In Kotlin, an object declaration already is a lazy, thread-safe singleton (the JVM runs its static initializer once). When creation needs an argument (e.g. Android's Room.databaseBuilder(context)), use double-checked locking with @Volatile: check without the lock, lock, then check again.

Pseudocode

CLASS Database
    PRIVATE CONSTRUCTOR                      // nobody else can call new
    PRIVATE STATIC VOLATILE instance = null

    STATIC FUNCTION getInstance()
        IF instance == null THEN             // 1st check: fast path, no lock once created
            LOCK Database.class
                IF instance == null THEN     // 2nd check: another thread may have won the race
                    instance = new Database()
        RETURN instance

Q14Implement a generic, resizable Stack, and use it to check balanced bracketsEasy

Problem. Write ArrayStack<T> with push, pop, peek, size and iteration, backed by an array that grows as needed. Then use it to validate "{[()]}".

Approach. Keep an array and a size index. When the array is full, double it: copying happens rarely, so push is amortized O(1). On pop, null out the vacated slot so the GC can free the object. For brackets: push openers; on a closer, the top of the stack must be its matching opener.

Pseudocode

CLASS Stack<T>
    items = array of capacity 2; size = 0

    FUNCTION push(x)
        IF size == capacity THEN items = copy of items with DOUBLE capacity   // amortized O(1)
        items[size] = x; size = size + 1

    FUNCTION pop()
        IF size == 0 THEN THROW "empty stack"
        size = size - 1
        x = items[size]; items[size] = null   // clear the slot so the GC can reclaim it
        RETURN x

    FUNCTION peek()  → items[size - 1]

// Use case: balanced brackets
FOR EACH ch IN text
    IF ch is an opener THEN push(ch)
    ELSE IF ch is a closer THEN
        IF stack empty OR pop() != matching opener THEN RETURN false
RETURN stack is empty

Kotlin

class ArrayStack<T> : Iterable<T> {
    private var items = arrayOfNulls<Any?>(2)
    var size = 0
        private set

    fun push(item: T) {
        if (size == items.size) items = items.copyOf(size * 2)   // grow: amortized O(1)
        items[size++] = item
    }

    fun pop(): T {
        if (isEmpty()) throw NoSuchElementException("stack is empty")
        val item = elementAt(--size)
        items[size] = null                     // avoid "loitering": a stale reference is a memory leak
        return item
    }

    fun peek(): T = if (isEmpty()) throw NoSuchElementException("stack is empty") else elementAt(size - 1)
    fun isEmpty() = size == 0

    @Suppress("UNCHECKED_CAST")
    private fun elementAt(i: Int) = items[i] as T   // erasure: the array is Any?, so cast on the way out

    override fun iterator() = object : Iterator<T> {  // iterate top → bottom without popping
        private var i = size
        override fun hasNext() = i > 0
        override fun next() = elementAt(--i)
    }
}

fun isBalanced(text: String): Boolean {
    val pairs = mapOf(')' to '(', ']' to '[', '}' to '{')
    val stack = ArrayStack<Char>()
    for (ch in text) {
        when (ch) {
            '(', '[', '{' -> stack.push(ch)
            ')', ']', '}' -> if (stack.isEmpty() || stack.pop() != pairs[ch]) return false
        }
    }
    return stack.isEmpty()
}

fun main() {
    val stack = ArrayStack<Int>()
    for (i in 1..5) stack.push(i)              // forces two resizes: 2 → 4 → 8
    println("${stack.toList()} size=${stack.size} peek=${stack.peek()}")
    println("${stack.pop()} ${stack.pop()} → ${stack.toList()}")
    println(listOf("{[()]}", "([)]", "((", "").map(::isBalanced))
}

  • Shrink to half when the stack is a quarter full, not half full, to avoid thrashing at the boundary.
  • In real code, use ArrayDeque (not java.util.Stack, which is synchronized and extends Vector).
Q15Min Stack: getMin() in O(1)Medium

Problem. Design a stack that supports push, pop, top and getMin, all in O(1).

Approach. Keep a second stack of minimums. Push onto it when the new value is ≤ the current minimum (the = matters for duplicates), and pop from it when the value being popped equals the current minimum. Its top is always the minimum of everything below.

Pseudocode

CLASS MinStack
    values = stack; mins = stack              // mins.top is always the minimum of values

    FUNCTION push(x)
        values.push(x)
        IF mins is empty OR x <= mins.top THEN mins.push(x)   // <= so duplicates are tracked

    FUNCTION pop()
        x = values.pop()
        IF x == mins.top THEN mins.pop()      // the current minimum is leaving
        RETURN x

    FUNCTION getMin() → mins.top              // O(1): no scanning

Kotlin

class MinStack {
    private val values = ArrayDeque<Int>()
    private val mins = ArrayDeque<Int>()

    fun push(x: Int) {
        values.addLast(x)
        if (mins.isEmpty() || x <= mins.last()) mins.addLast(x)
    }

    fun pop(): Int {
        val x = values.removeLast()
        if (x == mins.last()) mins.removeLast()
        return x
    }

    fun top() = values.last()
    fun getMin() = mins.last()
}

        println("push $x → min ${s.getMin()}")
    }
    repeat(3) {
        val popped = s.pop()
        println("pop $popped → min ${s.getMin()}")
    }
}

Q16Implement a Queue using two StacksMedium

Problem. Implement FIFO enqueue/dequeue using only stack operations (push, pop, peek, isEmpty).

Approach. Push new items onto an inbox stack. To dequeue, pop from an outbox stack. Only when the outbox is empty, move everything from the inbox into it. Reversing a stack turns LIFO into FIFO. Each element moves at most once, so the cost averages out to O(1).

Pseudocode

CLASS QueueFromStacks
    inbox = stack; outbox = stack

    FUNCTION enqueue(x)
        inbox.push(x)                         // always O(1)

    FUNCTION dequeue()
        IF outbox is empty THEN
            WHILE inbox not empty             // reversing a stack turns LIFO into FIFO
                outbox.push(inbox.pop())
        IF outbox is empty THEN THROW "empty queue"
        RETURN outbox.pop()

// Each element is moved at most once → amortized O(1) per operation

Kotlin

class QueueFromStacks<T> {
    private val inbox = ArrayDeque<T>()        // used strictly as a stack: addLast / removeLast
    private val outbox = ArrayDeque<T>()

    fun enqueue(x: T) = inbox.addLast(x)

    fun dequeue(): T {
        shift()
        if (outbox.isEmpty()) throw NoSuchElementException("queue is empty")
        return outbox.removeLast()
    }

    fun peek(): T { shift(); return outbox.last() }
    val size get() = inbox.size + outbox.size

    private fun shift() {
        if (outbox.isEmpty()) {
            while (inbox.isNotEmpty()) outbox.addLast(inbox.removeLast())
        }
    }

    override fun toString() = "in=$inbox out=$outbox"
}

fun main() {
    val q = QueueFromStacks<String>()
    q.enqueue("a"); q.enqueue("b"); q.enqueue("c")
    println(q)
    println(q.dequeue())                       // triggers the one-time transfer
    println(q)
    q.enqueue("d")                             // new items wait in the inbox
    println(q)
    println(List(3) { q.dequeue() })           // FIFO order preserved: b, c, then d
}

Q17Design an LRU Cache with O(1) get and putHard

Problem. Implement get(key) and put(key, value) for a fixed-capacity cache that evicts the least recently used entry, both in O(1).

Approach. Two structures together: a HashMap for O(1) lookup of a node, and a doubly linked list ordered by recency for O(1) move-to-front and remove-from-tail. Sentinel head and tail nodes remove all null edge cases. Each node stores its own key so eviction can also remove it from the map.

Pseudocode

CLASS LRUCache(capacity)
    map = HashMap<key, Node>                  // O(1) lookup
    list = doubly linked list                 // order of use: head = most recent, tail = least recent

    FUNCTION get(key)
        IF key NOT IN map THEN RETURN -1
        node = map[key]
        MOVE node TO head                     // it was just used
        RETURN node.value

    FUNCTION put(key, value)
        IF key IN map THEN
            update map[key].value; MOVE it TO head
        ELSE
            IF size == capacity THEN
                REMOVE list.tail FROM list AND map   // evict the least recently used
            node = new Node(key, value)
            ADD node AT head; map[key] = node

Kotlin

class LRUCache(private val capacity: Int) {
    private class Node(val key: Int, var value: Int) {
        var prev: Node? = null
        var next: Node? = null
    }

    private val map = HashMap<Int, Node>()
    private val head = Node(0, 0)              // sentinels: no null checks at the ends
    private val tail = Node(0, 0)

    init { head.next = tail; tail.prev = head }

    fun get(key: Int): Int {
        val node = map[key] ?: return -1
        unlink(node); addFront(node)
        return node.value
    }

    fun put(key: Int, value: Int) {
        map[key]?.let { it.value = value; unlink(it); addFront(it); return }
        if (map.size == capacity) {
            val lru = tail.prev!!
            unlink(lru); map.remove(lru.key)   // the node stores its key so we can remove it from the map
            println("  evict ${lru.key}")
        }
        val node = Node(key, value)
        addFront(node); map[key] = node
    }

    private fun unlink(n: Node) { n.prev!!.next = n.next; n.next!!.prev = n.prev }
    private fun addFront(n: Node) { n.next = head.next; n.prev = head; head.next!!.prev = n; head.next = n }

    override fun toString(): String {
        val keys = mutableListOf<Int>()
        var cur = head.next
        while (cur !== tail) { keys += cur!!.key; cur = cur.next }
        return "recent→old $keys"
    }
}

    override fun removeEldestEntry(eldest: MutableMap.MutableEntry<K, V>?) = size > capacity

Q18Observer pattern: build a type-safe EventBus with subscribe/unsubscribeMedium

Problem. Let components subscribe to event types and get notified when an event is published, without the publisher knowing who is listening.

Approach. Keep a map from event class → list of handlers. subscribe returns a Subscription handle used to unsubscribe. publish looks up handlers by the event's class and calls a snapshot copy of the list, so a handler can unsubscribe during dispatch without a ConcurrentModificationException. A reified overload gives the bus.subscribe<UserLoggedIn> { } call-site syntax.

Pseudocode

CLASS EventBus
    subscribers = Map<EventType, List<Handler>>

    FUNCTION subscribe(type, handler)
        subscribers[type].add(handler)
        RETURN a function that removes this handler   // caller MUST unsubscribe (e.g. in onDestroy)

    FUNCTION publish(event)
        FOR EACH handler IN copy of subscribers[typeOf(event)]   // copy: handlers may unsubscribe mid-loop
            handler(event)

Kotlin

fun interface Subscription { fun cancel() }

class EventBus {
    private val subscribers = mutableMapOf<Class<*>, MutableList<(Any) -> Unit>>()

    @Synchronized
    fun <T : Any> subscribe(type: Class<T>, handler: (T) -> Unit): Subscription {
        val wrapper: (Any) -> Unit = { handler(type.cast(it)) }
        subscribers.getOrPut(type) { mutableListOf() } += wrapper
        return Subscription { synchronized(this) { subscribers[type]?.remove(wrapper) } }
    }

    inline fun <reified T : Any> subscribe(noinline handler: (T) -> Unit) = subscribe(T::class.java, handler)

    fun publish(event: Any) {
        val handlers = synchronized(this) { subscribers[event.javaClass]?.toList().orEmpty() }
        handlers.forEach { it(event) }        // call outside the lock: handlers may publish too
    }
}

    bus.subscribe<CartUpdated> { println("badge: ${it.items} items") }

Q19Strategy pattern: pluggable payment methods and discount rulesMedium

Problem. Checkout must support card, UPI and wallet payments, plus optional discount rules, and adding a new payment type must not require editing Checkout.

Approach. Define a PaymentMethod interface, with one class per strategy, and inject the strategy into Checkout instead of branching on a type with if/when. Simple strategies don't need a class at all: a discount rule is just a function (Long) -> Long. A sealed result type forces callers to handle both success and decline.

Pseudocode

INTERFACE PaymentMethod
    FUNCTION pay(amount) → Result            // each strategy implements the same contract

CLASS CardPayment   IMPLEMENTS PaymentMethod    adds a 2% fee
CLASS UpiPayment    IMPLEMENTS PaymentMethod    no fee
CLASS WalletPayment IMPLEMENTS PaymentMethod    fails if the balance is too low

CLASS Checkout(discountRule)                  // the strategy is INJECTED, not chosen with if/else
    FUNCTION checkout(total, method)
        RETURN method.pay(discountRule(total))

// Adding a new payment type = a new class. Checkout never changes (Open/Closed principle).

Kotlin

sealed interface PaymentResult {
    data class Success(val charged: Long, val via: String) : PaymentResult
    data class Declined(val reason: String) : PaymentResult
}

interface PaymentMethod {
    fun pay(amountCents: Long): PaymentResult
}

class CardPayment(private val last4: String) : PaymentMethod {
    override fun pay(amountCents: Long) = PaymentResult.Success(amountCents + amountCents * 2 / 100, "card *$last4")
}

class UpiPayment(private val upiId: String) : PaymentMethod {
    override fun pay(amountCents: Long) = PaymentResult.Success(amountCents, "upi $upiId")
}

class WalletPayment(private var balanceCents: Long) : PaymentMethod {
    override fun pay(amountCents: Long): PaymentResult {
        if (amountCents > balanceCents) return PaymentResult.Declined("wallet has $balanceCents")
        balanceCents -= amountCents
        return PaymentResult.Success(amountCents, "wallet")
    }
}

// Strategies can also be plain functions: a discount rule is just (Long) -> Long.
val noDiscount: (Long) -> Long = { it }
val tenPercentOff: (Long) -> Long = { it - it / 10 }

class Checkout(private val discount: (Long) -> Long = noDiscount) {
    fun checkout(totalCents: Long, method: PaymentMethod): String =
        when (val result = method.pay(discount(totalCents))) {     // exhaustive over the sealed result
            is PaymentResult.Success -> "charged ${result.charged} via ${result.via}"
            is PaymentResult.Declined -> "declined: ${result.reason}"
        }
}

    println(sale.checkout(10_000, UpiPayment("ann@bank")))
    val wallet = WalletPayment(5_000)
    println(sale.checkout(5_000, wallet))
    println(sale.checkout(5_000, wallet))
}

Q20Design a rate limiter class (token bucket)Hard

Problem. Allow at most N requests per second with short bursts allowed, e.g. to throttle API calls or button taps. tryAcquire() returns whether this call may proceed.

Approach. A bucket holds up to capacity tokens and refills at refillPerSecond. Each request spends one token. Refill lazily: on every call, add elapsed × rate tokens, capped at capacity. No background timer is needed. Inject a Clock so tests can move time forward deterministically instead of sleeping.

Pseudocode

CLASS TokenBucket(capacity, refillPerSecond, clock)
    tokens = capacity; lastTime = clock.now()

    FUNCTION tryAcquire()      SYNCHRONIZED
        now = clock.now()
        tokens = MIN(capacity, tokens + (now - lastTime) * refillPerSecond)   // lazy refill: no timer thread
        lastTime = now
        IF tokens >= 1 THEN
            tokens = tokens - 1; RETURN true   // request allowed
        RETURN false                           // over the limit → reject or retry later

// capacity = the allowed burst size, refillPerSecond = the steady-state rate

Kotlin

fun interface Clock { fun nanos(): Long }

class TokenBucket(
    private val capacity: Int,
    private val refillPerSecond: Double,
    private val clock: Clock = Clock(System::nanoTime),   // injectable → deterministic tests
) {
    private var tokens = capacity.toDouble()
    private var last = clock.nanos()

    @Synchronized
    fun tryAcquire(): Boolean {
        val now = clock.nanos()
        tokens = minOf(capacity.toDouble(), tokens + (now - last) / 1e9 * refillPerSecond)
        last = now
        if (tokens < 1) return false
        tokens -= 1
        return true
    }
}

fun main() {
    var fakeNow = 0L
    val limiter = TokenBucket(capacity = 3, refillPerSecond = 1.0, clock = { fakeNow })

    println("t=0s   " + List(5) { limiter.tryAcquire() })   // burst: 3 allowed, then rejected
    fakeNow += 500_000_000
    println("t=0.5s " + List(1) { limiter.tryAcquire() })   // only half a token so far
    fakeNow += 1_500_000_000
    println("t=2s   " + List(3) { limiter.tryAcquire() })   // 2 tokens refilled
    fakeNow += 60_000_000_000
    println("t=62s  " + List(4) { limiter.tryAcquire() })   // capped at capacity, not 60
}

t=0.5s [false]
t=2s   [true, true, false]
t=62s  [true, true, true, false]
Time: O(1) per call · Space: O(1)

Follow-ups interviewers ask:

  • Fixed window counters allow 2× bursts at window edges; sliding log is exact but O(requests) memory; token bucket is O(1) and allows controlled bursts.
  • Use System.nanoTime() (monotonic), not currentTimeMillis(), which can jump when the wall clock changes.
  • Per-user limits: a ConcurrentHashMap<UserId, TokenBucket> with eviction of idle buckets.
  • On the client side, OkHttp interceptors and Flow debounce/throttle operators solve similar problems.
